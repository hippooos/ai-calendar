# 产品范围

## 用户与问题

工作、生活和学习安排较多的个人用户，经常需要在脑中的目标、待办清单与日历之间来回整理。AI 日历将自然语言转为可核对、可修改、经用户确认的近期日程。

## 功能流程

- 明确安排：识别日期、开始时间和时长；关键缺口进入追问。
- 抽象目标：转换为具体行动与任务模板；推断内容作为可修改假设呈现。
- 混合输入：同一次输入可以包含明确安排和抽象目标。
- 排程：默认 14 天，明确一个月/30 天时使用 30 天；保留硬星期、硬时段与其他约束，考虑既有日历和睡眠。
- 草案：展示排入项、冲突、未排入原因和假设；ready 状态允许修改、删除与整组确认。
- 持久化：确认后写入本应用日历；本地用 SQLite，部署配置支持 PostgreSQL。
- 修改和删除：已有日程可通过界面手动操作；自然语言链路聚焦新增。

## 使用范围

- 使用模式：单用户管理个人安排；部署访问采用共享访问码，不提供多人账户与数据隔离。
- 数据范围：读写本应用日历，不同步外部日历。
- 操作方式：自然语言用于创建计划；已有日程通过界面手动修改和删除。
- 计划执行：用户确认后生成日程；提醒、自动续排和完成情况跟踪不属于本应用功能。
- 调用控制：模型通过后端调用，共享访问码不包含每用户额度、调用限流或费用硬上限。

## 交互取舍

1. 优先追问影响排程的缺口，避免把所有模糊条件都转成问卷。
2. 用户明确表达的限制优先；AI 推断需要标明，不能悄悄变成用户承诺。
3. 模型生成建议，排程器决定合法时间；无法满足时说明不足，不静默放宽硬约束。
4. 用户确认后才产生日程，模型回答本身不直接写入日历。

## 典型场景

| 输入场景 | 处理方式 |
| --- | --- |
| 给出日期、开始时间和时长 | 提取固定安排，进入草案 |
| 只说明某天下午有会议 | 追问具体开始时间 |
| 给出目标、每周频率和时间偏好 | 生成行动模板，在规划窗口内安排时间 |
| 指定时间与已有日程冲突 | 展示冲突或未排入原因，由用户调整草案 |
